# CScore → подбор и проверка армирования БНС и стены в грунте (эксперимент)

**Задача:** не писать свой модуль СП 63, а использовать отдельное ядро **CScore**
из проекта [OpenCS](https://github.com/rumata-ap/OpenCS) для пакетного подбора
продольного армирования и для проверки уже принятых сечений. Все сопротивления,
η, φn, раскрытие трещин и случайный эксцентриситет вычисляет CScore; Python и
C#-адаптер готовят исходные данные, вызывают ядро и проверяют ответ.

**Не применять для выдачи КЖ.** Во всех результатах `verified_for_design=false`.
Статус «пройдено» относится к отдельному выполненному условию ядра, а не к
разрешению выпуска рабочей документации.

### Что подключено через CScore

| Проверка | Метод CScore | Состояние |
|---|---|---|
| Прочность нормального сечения N–Mx–My | `LimitForceSolver.AllFactor` | Подбор и проверка; сверено с АРБАТ |
| Случайный эксцентриситет в двух плоскостях | `Sp63MemberContext.AccidentalEccentricity/EffectiveEccentricity` | Ручная проверка и CLI; при нулевом моменте — оба знака |
| Второй порядок η | `Sp63.RodEtaWiring` + `LimitForceSolver` | Нужны l₀x/l₀y и доля длительного момента |
| Образование и раскрытие трещин | `CrackWidthSolver.Compute` | Основной режим `arbat_conservative` (предварительный), авторский `native_refined` |
| Q: бетонная полоса и наклонное сечение (8.55/8.56) | `Sp63Shear.ShearInclinedChecker` | Прямоугольник; круглая БНС — только через принятое приведение |
| Момент наклонного сечения (8.63) | `ShearInclinedChecker` + `InclinedSectionModel.AppliedMoment` | Нужны k и расстояния до опор в обе стороны |

η увеличивает только момент нормального сечения; Q и наклонный момент
проверяются по исходным внешним усилиям (СП 63 пп. 8.1.32–8.1.35),
см. [eta-shear-sp63-2026-10-19.md](docs/research/eta-shear-sp63-2026-10-19.md).

### Что не сделано

- Анкеровка, обрывы, стыки, переходы шага хомутов, полные конструктивные требования.
- Расчёт целого элемента по реальной эпюре и опорам; локальные Q/M считаются
  на `ConstantProfile` выбранной отметки.
- Нормативное обоснование навивки круглой БНС. Приняты допущения инженера:
  геометрия ВНИИГС 1984 `b=0,885D`, `h0=b−a` и «один виток — две ветви»
  (`vniigs_1984_two_legs`); есть режим «только бетонная часть» (qsw=0).
  Сверки спирали с АРБАТ нет. Q при двухосном изгибе БНС не поддерживается.
- Методика трещин `arbat_conservative` — предварительная оценка, а не копия АРБАТ;
  при неполной длительной нагрузке — разделение по п. 8.2.6 с отдельной длительной N
  (ψs = 1 в запас, если длительная нагрузка ниже Mcrc).
- Направление ea при двухосном изгибе в CLI-подборе пропорционально исходному
  моменту — отдельно не верифицированная гипотеза.
- Импорт из живого PLAXIS 2D v22.01 не проверен.

## Запуск

### Windows-архив (рабочий ПК)

1. **Actions → CScore pile PoC Windows → Run workflow** (запуск только ручной).
2. Скачать артефакт **cscore-pile-windows**: в нём `CScorePileRunner.exe`
   (self-contained, .NET SDK не нужен), Python-часть, примеры и результаты прогонов.
3. Интерфейс: `start_workbench.bat` (нужен Python 3.10+, сторонние пакеты не нужны).
   Стартовый экран — ручная проверка сечения N/Mx/My/Q; там же переход к подбору
   по эпюрам. Инструкция: [workbench-guide.md](docs/workbench-guide.md),
   проверки принятого сечения: [cscore-connection-cycle.md](docs/cscore-connection-cycle.md).
4. Командная строка: `python pile_rebar.py demo_bns.json --runner CScorePileRunner.exe`
   → `results/pile_results.json` и `.csv`; для стены —
   `python wall_rebar.py wall_cages.json --runner CScorePileRunner.exe`.

Готовые ручные примеры: `member_length15_manual.json` из архива (автоматический ea по CScore,
ожидается K≈8,00) и `examples/verification/member_length15_arbat20_manual.json`
из репозитория (готовые моменты при ea=20 мм, K≈6,346). Оба открываются в сборке №46.

### Машина разработчика (Git + .NET 10 SDK)

```powershell
./scripts/setup.ps1
python -m unittest discover -s tests -v
python pile_rebar.py examples/demo_bns.json --runner publish/CScorePileRunner.exe
python workbench_app.py --runner publish/CScorePileRunner.exe
```

Через DLL: `--runner путь/к/CScorePileRunner.dll` (нужен .NET runtime).

## Формат примера подбора

`examples/demo_bns.json`:

- `pile`: диаметр БНС, защитный слой до внешней грани хомута/спирали, диаметр этой поперечной арматуры, минимальный геометрический просвет, параметры дискретизации сечения.
- `materials`: **явно заданные** расчётные характеристики материалов; это демонстрационные числа, а не автоматически выбранные нормативные значения.
- `loads`: совместно действующие `n_kn`, `mx_knm`, `my_knm`, идентификатор комбинации. **CScore: N отрицательная при сжатии**, положительная при растяжении. Остальные знаки и оси необходимо верифицировать при импорте PLAXIS.
- `search`: разрешённые числа и диаметры стержней, повороты полярной раскладки.
- `sls_probe` (необязательно): нормативные SLS-сочетания с явным `"force_basis":{"uls":"design","sls":"normative"}`. SLS считается только для кандидатов, прошедших ULS; иначе — `not_evaluated_uls_fail` / `not_evaluated_uls_indeterminate`. Пример: `examples/verification/P800_sls_preselection_example.json`.

Единицы: **мм** для размеров и диаметров, **кН**, **кН·м**, **кПа** для материалов. Коэффициент использования `utilization = 1 / factor`. Несходимость, пропуск или испорченный ответ дают `indeterminate`, **никогда** не успех. Самый лёгкий вариант среди `pass_uls` — предварительный, не готовое решение для КЖ. Варианты считаются последовательно; приоритет — надёжность контракта, а не скорость.

## Случайный эксцентриситет в подборе

Учёт задаётся **явно**. В режиме `sp63_stat_determinate` для сжимающей N<0 эксцентриситет готовит CScore (`Sp63MemberContext`); добавочный момент направлен вдоль вектора (Mx, My) исходного сочетания.

```json
"eccentricity": {
  "mode": "sp63_stat_determinate",
  "static_scheme": "statically_determinate",
  "effective_length_mm": 3000
}
```

При Mx=My=0 задай `zero_moment_axis` (`mx_positive`, `mx_negative`, `my_positive`, `my_negative`), иначе расчёт остановится с ошибкой. Альтернативы: `{"mode":"already_in_loads"}` — моменты уже включают поправку; `{"mode":"research_none"}` — исследовательское сравнение без неё. Без блока старые JSON считаются, но результат помечается неполным и `selected_uls_candidate` не выдаётся. В `forces_audit` и CSV сохраняются исходные и эффективно проверенные N/M.

В ручной проверке сечения ea готовится в обеих плоскостях по фактической длине и статической схеме, отдельно от l₀x/l₀y для η; двойное добавление к подтверждённым готовым моментам запрещено.

## Обновления OpenCS/CScore

Версия исходников и патч зафиксированы в `config/opencs.lock.json`; при сборке проверяются SHA и хеш патча. Еженедельный workflow `Check upstream CScore updates` при релевантных изменениях в `CScore/`, тестах и математических зависимостях обновляет **одну GitHub Issue**; SHA он не меняет и тяжёлую сборку не запускает.

Переход на новую версию: отдельная ветка → изучение изменений → обновление lock, pin SHA и проверка применимости патча → CI → повторные сверки с АРБАТ (в том числе пограничный Ø800 T08) и контроль новых несходимостей → перенос в основную ветку.
