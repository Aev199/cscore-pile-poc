# Возврат согласованной методики трещин на основе CScore

По запросу пользователя от 19.10.2026 восстановлен основной режим
`arbat_conservative`; `native_refined` доступен отдельным выбором. Восстановлен
`RunCrackProbe` из родителя коммита `b20a2af` с сохранением новой передачи
усилий после η. Прочность, Q, наклонный момент и η не менялись.

## Что именно восстановлено

Для совпадающих полной и длительной нагрузок используются напряжения
до трещинообразования, полученные CScore, и прежняя дополнительная оценка ψs.
Оценка не опускается ниже авторского CScore. При несовпадающих нагрузках
используется прежний вариант ψs=1 для компонентов ширины. Это предварительная
методика, не подтверждённая копия Арбата. Пограничная полоса ±3% — историческое
правило направления на рассмотрение инженером, не изменение пределов СП.

Также восстановлен отдельно обозначенный расчёт кратковременного раскрытия
через повторный вызов CScore при трещинах только от полной нагрузки. Такой
случай не получает предварительного допуска: только превышение или рассмотрение
инженером. Ошибка сходимости не считается отсутствием трещин.

Ручной интерфейс показывает выбранную оценку, исходные ширину и коэффициент
CScore сохраняет в подробностях. Консервативные результаты явно обозначены
как предварительные; источник — `Application.ArbatConservativeWithCScore`.
В сохранённом файле выбор не меняется автоматически. Новые проекты получают
консервативный режим; старые с явно указанным native сохраняют native.

## Повторная сверка

Исследовательская матрица: 7 сечений, 70 сочетаний. 62 численных результата,
из них 3 — отдельно отмеченное неподтверждённое восстановление кратковременных
трещин; 8 остаются неопределёнными. В Арбате раскрытие напечатано для 27 случаев.
Отсутствующий коэффициент Арбата не считается нулём.

На тех же 9 предварительно сопоставимых случаях средняя абсолютная относительная
разница длительного коэффициента — **4,92936%**, кратковременного — **3,98597%**.
Длительное отклонение воспроизводит протокол 16.10; кратковременное учитывает
уже существовавшее исправление равенства ширин при полностью длительной нагрузке.
Оставшиеся случаи исключены по геометрии, несовпадению длительного N и
неподтверждённому восстановлению. Эти проценты не характеризуют все 70 случаев.

Отдельно выполнены **42 расчёта через настоящий ручной интерфейс**. 36 —
несжатые сочетания при явно принятой гипотезе защитного слоя; 6 со сжатием
сохранены только как диагностика: эксцентриситет статически определимой схемы
не воспроизведён. 28 сочетаний недоступны ручной форме: второй момент и
двухрядное расположение стержней.

Кратковременные коэффициенты из реального продукта:

| Сечение / сочетание | Арбат | Сборка 43, native | Восстановленный основной режим |
|---|---:|---:|---:|
| 400×600 / №2 | 1,268 | 0,957795 | **1,304402** |
| 400×600 / №7 | 1,408 | 0,873110 | **1,431405** |
| Ø600 / №9 | 1,100 | 0,788011 | **1,212286** |

Все три известных расхождения с предварительным прохождением против превышения
Арбата теперь дают предварительное превышение. Это не доказывает универсальное
совпадение либо универсальную консервативность относительно Арбата.

## Исправление геометрии ручного режима

В ручной проверке прямоугольника ранее передавались эквивалентные равномерные
координаты продольных стержней. Теперь передаются физические координаты,
показанные на схеме. Регрессия для 400×600, 4Ø25 на каждой грани проверяет
x=±137,5 мм и y=±237,5 мм. Профильный расчёт стены сохраняет ранее принятую
эквивалентную арматуру по ширине захватки.

Это не завершает воспроизведение примера 15 м: форма пока не задаёт второй
момент и не готовит эксцентриситет по двум плоскостям автоматически.

## Проверка и воспроизведение

- 193 Python-теста; настоящая сборка Release адаптера; проверка JavaScript.
- Настоящий браузер: расчёты СВГ/БНС, SLS/η/Q/наклонный M, сохранение и открытие
  выбранной методики, отдельный запуск native.
- `tools/verify_agreed_crack_method.py` проверяет четыре численных ориентира,
  именно коэффициенты отчёта продукта и неизменность исходных результатов
  CScore между двумя режимами. Проверка добавлена в Windows CI.
- `tools/workbench_smoke.py` проверяет прежний профильный процесс реальным ядром.

```sh
python tools/verify_agreed_crack_method.py --runner publish/CScorePileRunner.exe
python tools/cross_section_sls_matrix.py --runner publish/CScorePileRunner.exe --layout arbat_stated --out results/restored
python tools/compare_arbat70_crackwidth.py --csv results/restored/cross_section_sls_matrix.csv --out results/restored-comparison
```

Численные ссылки, хеши семи исходных RTF, сводки сборки 43 и восстановленного
ручного режима сохранены в `data/restored-cracks-2026-10-19/`.
Скрипт браузерной сверки — `tools/research/compare_arbat_manual_reports.cjs`;
нужны Playwright/Chromium, переменная `CSCORE_RUNNER` и запуск из корня репозитория.
