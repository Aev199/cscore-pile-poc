# Семь отчётов АРБАТ: полный прогон через ручную проверку продукта

Пользователь передал семь протоколов АРБАТ 21.1.9.3 (7 сечений × 10 сочетаний)
как ориентир по коэффициентам использования; допустимое расхождение — 5 %.
Хеши RTF совпадают с `restored-cracks-2026-10-19/source-sha256.json`: это те же
отчёты, что и в прежних сверках трещин. Новое здесь — сравнение **всех**
напечатанных коэффициентов через текущий ручной режим с My и автоматическим ea,
а также исправление методики SLS по результатам сверки.

## Постановка

- Каждое сочетание — один вызов `workbench.model.check_adopted(single_section=True)`,
  как в ручном интерфейсе; формулы и коэффициенты не подбирались.
- Из отчётов: B30 (γb1=0,9), A500, длина 3 м, μ=1 в обеих плоскостях,
  статически определимая схема, ea «по СП 63», γf=1, «коэффициент длительной части» k_дл
  (доля длительной нагрузки, не ψs!) относится ко всем усилиям: SLS N_l = k_дл·N, M_l = k_дл·M.
  Продукт: ea готовит CScore (`Sp63MemberContext`), η — `RodEtaWiring` при l₀=3 м.
- АРБАТ My/Mz → Mx/My ручной формы. Для прямоугольника усилия на сечение
  пересчитаны в погонные один раз (как режим «на сечение» формы); для БНС — `per_member`.
- a₁ трактуется как расстояние от грани до поверхности продольного стержня
  (принятая в репозитории трактовка). Совпадение прочности ниже её подтверждает.
- 400×400 с двумя рядами (2Ø16 + 2Ø16, просвет 20 мм) ручная форма не задаёт;
  явные координаты стержней переданы в тот же запрос runner.
- Сравниваемые величины продукта: `normal_member_strength` (с η; максимум по знакам ea),
  `crack_width_short/long` в основном режиме `arbat_conservative`, N/Ncr из диагностики η.

## Прочность нормального сечения

70 из 70 сочетаний рассчитаны. Для 64 коэффициентов АРБАТ ≥ 0,05 максимальное
расхождение **1,41 %**, среднее 0,56 %. Шесть малых коэффициентов (0,005–0,048)
совпадают с точностью печати АРБАТ (три знака). Вердикты «проходит/не проходит»
совпадают во всех 70 случаях, включая пограничный 400×400 T6 (1,006 / 1,011).

| Сечение | Сочетаний с K ≥ 0,05 | Макс. расхождение |
|---|---:|---:|
| 300×500, 2+2Ø20 | 10 | 0,84 % |
| 400×400, два ряда Ø16 | 10 | 0,80 % |
| 400×600, 3+3Ø20 | 9 | 0,74 % |
| 500×700, 4+4Ø25 | 9 | 1,10 % |
| Ø600, 8Ø20 | 9 | 1,40 % |
| Ø800, 16Ø25 | 9 | 1,23 % |
| Ø1000, 20Ø28 | 8 | 1,41 % |

Коэффициент АРБАТ здесь — «прочность по предельному моменту»; продукт выдаёт
`AllFactor`. При N ≠ 0 это разные определения запаса, но на этих данных разница
в пределах 1,4 %. Строки АРБАТ «деформации в сжатом бетоне / растянутой арматуре»
и «предельная гибкость» отдельного аналога в отчёте продукта не имеют.

## Раскрытие трещин

Первый прогон выявил два отличия методики продукта от АРБАТ; оба исправлены
(раздел «Исправление» ниже). Таблица `comparison.csv` — уже после исправления.

АРБАТ не печатает трещины при отказе по прочности; продукт в этих случаях
SLS не выполняет (`not_evaluated_uls_fail`) — поведение совпадает.

| Группа | Пар | Расхождение | В пределах 5 % |
|---|---:|---|---:|
| k_дл = 1 (N = 0, растяжение, сжатие T6) | 42 | +1,1…+7,2 %, среднее 3,3 % | 38 |
| k_дл = 0,5, длительная часть с трещинами | 8 | +2,2…+7,6 % | 4 |
| k_дл = 0,5, длительная часть ниже Mcrc (ψs = 1) | 4 | +5,9…+22,7 % | 0 |

Все 54 пары **в запас** (продукт ≥ АРБАТ), занижений нет. Свыше 5 %:
500×700 T4 (+7,1/+7,2 %) и Ø600 T4 (+5,3 %) — изгиб по Mz; k_дл = 0,5 — длительное
раскрытие 400×600 T9 (+7,1 %), T10 (+5,5 %), Ø600 T9 (+7,6 %), T10 (+6,5 %);
500×700 T9/T10 (+22 %, ψs = 1 — принятое консервативное допущение).
Сжатые T6: +1,1…+2,7 % (было +20…+31 %).

Вердикт расходится в одном случае: 300×500 T1 длительное 0,987 / 1,032 (+4,5 %, в запас).

**Трещины есть у продукта, у АРБАТ нет:** Ø600 T1, Ø800 T2/T3/T9. Продукт находит
Mcrc ниже действующего момента (Ø800: 155,6 < 180 кН·м); ширины ниже допустимых,
вердикт тот же. Mcrc АРБАТ в отчёте не печатается.

Авторский `native_refined` хранится в CSV для справки: при k_дл = 1 и N ≥ 0 он на 18–61 % ниже АРБАТ.

## Исправление методики SLS (19.10.2026)

Исходное допущение: АРБАТ считает правильно; где его способ нельзя воспроизвести,
ψs = 1 в запас (СП 63 п. 8.2.15).

1. **SLS-усилия без ea и η.** Случайный эксцентриситет (п. 8.1.7) и η (п. 8.1.15)
   относятся к расчёту по прочности. Раздел 8.2 использует нормативные усилия как
   заданы; так же считает АРБАТ. Раньше продукт добавлял ea и η к SLS: сжатые T6
   давали +20…+31 %. Устойчивость элемента при SLS по-прежнему показывается.
2. **Длительная N и разделение по п. 8.2.6.** Образование трещин проверяется по
   полной нагрузке; a_crc1 и a_crc3 — по длительной (N_l, M_l), a_crc2 — по полной (N, M).
   CScore принимает одну N, поэтому каждое состояние — отдельный вызов той же
   согласованной оценки «полностью длительной» нагрузки:
   a_crc1 = w(N_l, M_l), a_crc3 = a_crc1/1,4, a_crc2 = w(N, M)/1,4,
   a_crc,дл = a_crc1, a_crc,кр = a_crc1 + a_crc2 − a_crc3.
   Раньше длительная часть получала полную N: при сжатии T10 длительное раскрытие
   было **ниже АРБАТ** до −12 %; ветвь ψs = 1 для всех составляющих давала +10…+20 %.
3. **Длительная нагрузка ниже Mcrc, трещины от полной уже есть:** a_crc1 по ψs = 1 —
   ширина CScore при ψs = 1 для полного состояния, масштабированная отношением
   напряжений в арматуре сечения с трещиной (N_l, M_l)/(N, M). ls, φ2, Es — полного
   состояния. Раньше длительное раскрытие было 0 со статусом «проверка инженером».

Для k_дл = 1 расчёт не изменился. Авторский `native_refined` с разными N отказывает
(`native_refined_requires_single_axial_force`): решатель автора принимает одну N.
В ручной форме добавлено поле «N длительное» (пусто — равно N).

## N/Ncr

Прямоугольники: в пределах 4,1 % (значения 0,007–0,059). Круги: 0,0018–0,0163
против 0,001–0,012 — АРБАТ печатает три знака, но для Ø600 T6 расхождение 36 %
реальное (жёсткость круга в η). Влияние на прочность малое: η ≈ 1,01, прочность
круглых сечений совпадает в пределах 1,41 %.

## Воспроизведение

```sh
python tools/research/compare_arbat_seven_full.py --rtf-dir <папка с RTF> --runner publish/CScorePileRunner.exe
```

Нужен `pandoc`. Результаты: `data/arbat-seven-full-2026-10-19/comparison.csv`
(все пары, нативный результат, основание оценки) и `arbat-reference.json`
(все строки коэффициентов АРБАТ). Прогон выполнен на Linux-сборке того же
закреплённого ядра с патчем φn; Windows-сборкой не повторялся.
