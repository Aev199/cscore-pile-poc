# Проверки принятого сечения через CScore

Подключение не меняет перебор вариантов и схему армирования. Команда
**«Проверки CScore»** проверяет уже принятое армирование на заданных отметках.
Результат показывается отдельно от предварительного подбора N/M.

Для круглой БНС в «Данные проверок…» теперь доступны два варианта Q.
«Без вклада навивки · бетонная часть» не требует χ, осевого диаметра
навивки или её конструктивного подтверждения. Задайте a, основание
применения приведённой геометрии и подтвердите выбранную модель.
Данные о поперечной арматуре могут оставаться выключенными.
Сопротивление вычисляет CScore при qsw=0; новая формула не вводится.

Если проверка без навивки не пройдена, это означает недостаточность
бетонной части в принятой модели, а не доказанный отказ сваи с навивкой.
В отчёте этот режим подписан отдельно. Приведение по исторической ВНИИГС
b=0,885D, h0=b−a остаётся явным допущением инженера при использовании
совместно с СП 63. Полный нормативный допуск конструкции не выдаётся.

«Приведённая навивка · исследовательский режим» сохраняет прежние
требования к геометрии и обоснованию χ. Ранее сохранённые проекты
не переводятся автоматически в другой режим. Выбор нового режима
снимает подтверждение; параметры навивки при сохранении бетонного
режима очищаются, скрытый ненулевой вклад не допускается.

## Какие методы вызываются

| Проверка | Метод закреплённого CScore |
| --- | --- |
| Прочность нормального сечения N/M | `LimitForceSolver.AllFactor` |
| Образование трещин, продолжительное/непродолжительное раскрытие | `CrackWidthSolver.Compute` |
| Второй порядок, режим расчёта коэффициента η | `Sp63.RodEtaWiring.Apply` |
| Прочность с учётом η | `LimitForceSolver.AllFactor` на усилиях, подготовленных `RodEtaWiring` |
| Устойчивость при SLS | `RodEtaWiring.Apply` (только устойчивость; трещины считаются по заданным SLS-усилиям без η, СП 63 разд. 8.2) |
| Бетонная полоса, наклонное сечение Q и наклонный момент | `Sp63Shear.ShearInclinedChecker.Check`, отдельные условия 8.55 / 8.56 / 8.63 |
| Применимость автоматического Q к форме | `Sp63Shear.Sp63ShearApplicability.Evaluate` |

В программе нет собственных формул несущей способности или поправок к
раскрытию трещин. Подготовка единиц/геометрии, выбор исходных усилий и
валидация ответа отделены от расчёта ядра. Базовый commit OpenCS закреплён; к нему автоматически применяется проверяемый
патч φn и слагаемого 8.62. [Исправления и проверки](research/phi-n-fix-2026-10-18.md).

## Работа инженера

1. Задайте совместные усилия, материалы и принятое армирование.
2. В **«Данные проверок…»** выберите учёт второго порядка: неизвестен,
   уже учтён в исходной модели, расчёт η в CScore или только сечение.
   Режим CScore требует обе расчётные длины L0x/L0y, долю длительного момента
   и подтверждение учёта случайного эксцентриситета в исходных усилиях.
3. Для запроса наклонного момента задайте коэффициент включения продольной
   арматуры k, подтвердите анкеровку и введите расстояния до опор в обе
   стороны выбранной отметки: +s вниз, −s вверх. Эти два расстояния не
   копируются друг из друга и не распространяются на другие отметки.
   Пустое поле означает отсутствие данных; 0 означает отсутствие опоры,
   поэтому проверка наклонного момента при 0 не запускается.
4. Нажмите **«Проверки CScore»**. В инспекторе сечения показаны все проверки,
   сочетания, коэффициенты, раскрытие в мм и причины пропуска.

Изменения исходных данных сбрасывают результаты. Замена таблицы усилий,
импорт PLAXIS или смена типа конструкции сбрасывают привязку к опорам,
подтверждение анкеровки и декларацию второго порядка. Сохранение проекта
включает исходные данные проверок, но не переносит старые результаты.

## Границы расчёта

- Это проверки **заданных сечений**, а не доказательство выполнения условий
  между отметками и по всей конструкции. Локальные Q/M рассчитываются на
  штатном `ConstantProfile` и остаются исследовательскими.
- Автоматический нормативный Q в закреплённом CScore ограничен сплошным
  прямоугольником. Для круглой БНС без явно принятой приведённой модели
  возвращается «неприменимо» с причинами самого CScore. Отдельно подключён
  режим пользовательского приведённого сечения со спиральной навивкой:
  геометрия ВНИИГС 1984 и принятая модель двух условных ветвей на полный
  шаг витка. Прежний режим с ручным χ и проекцией витка сохранён для
  совместимости. Все сопротивления считает CScore.
  Это не автоматически обоснованная нормативная модель и не сверка с АРБАТ;
  [параметры и ограничения](research/circular-shear-equivalent-section-2026-10-18.md).
- Переходы шага хомутов не рассчитываются своей методикой. Локальное
  сечение использует принятый шаг своей зоны; на общей границе разных
  шагов проверка отклоняется, поскольку одного локального шага нет.
- При расчёте η нормальный момент изменяется ядром. Локальные Q и наклонный
  момент 8.63 CScore проверяет по заданному исходному `ConstantProfile`.
  η не подменяет профиль внешних усилий и не отключает эти проверки.
  Текущий пул и границы постановки: [cscore-connection-status.md](cscore-connection-status.md).
- `CrackWidthSolver` принимает одну N. При разных полной и длительной частях
  основной режим считает полное и длительное состояния отдельными вызовами
  и собирает ширины по п. 8.2.6; авторский режим с разными N не выполняется.
  Случаи, которые ядро не определило, не восстанавливаются своим решателем.
  После отказа/неопределённости ULS расчёт SLS пропускается.
- Неустойчивость при ULS и SLS показана отдельными результатами. Известный
  отказ одного направления Q/M сохраняется, даже если второе направление
  не удалось проверить; неполная проверка не может стать успешной.
- Коэффициент анкеровки — исходное условие, не расчёт длины анкеровки.
  Проверки длины анкеровки, обрывов и конструктивных требований отложены
  до этапа армирования и явно показаны невыполненными.
- Во всём отчёте `verified_for_design=false`. Статусы «пройдено» относятся
  к отдельным выполненным условиям ядра, а не к разрешению выпуска КЖ.

## Проверка подключения

`tools/connection_smoke.py` выполняет настоящим CScore N/M, образование и
раскрытие трещин, Q, наклонный момент, η и потерю устойчивости. Отдельно
проверяются отсутствие SLS, пропуск после отказа ULS, нулевые опоры,
неустойчивость только при SLS и известный отказ при неполной проверке
противоположного направления.

Браузерный сценарий проверяет сохранение направленных расстояний до опор,
валидацию полей, полный путь браузер → HTTP → CScore → отчёт и удаление
старого отчёта после ошибки повторного запуска. Windows workflow включает
оба сценария; новая Windows-сборка проверяется отдельно.
