# Сечения — первый интерфейс

## Запуск
Распакуйте Windows-архив и запустите `start_workbench.bat`.
Нужен обычный Python 3.10+; для ручного ввода сторонние пакеты не нужны.
Откроется локальная страница в браузере. Окно Python оставьте открытым.
CScorePileRunner.exe должен находиться рядом с workbench_app.py.
Из исходников: `python workbench_app.py --runner publish/CScorePileRunner.exe`.

## Работа
1. Выберите стену или БНС. Введите геометрию и фон. Для стены фон задаётся
   на одну грань одного каркаса; каркасы одинаковые.
2. «Таблица усилий»: вставьте семь столбцов из Excel. Заголовок можно опустить.
   `z;case;basis;n;m;q;m_long` — отметка, фаза/сочетание, ULS/SLS, N, M, Q,
   длительная M. Десятичная запятая допустима. N<0 — сжатие.
3. Укажите масштаб исходных усилий. Если Plate представляет сваи,
   усилия на метр умножаются на шаг свай один раз. Для стены — только на метр.
4. Проверьте материалы (кПа) и параметры трещин (мм). Исходные значения —
   иллюстративный пример. Подтвердите проверку материалов; учёт эксцентриситета
   подтверждайте только если он действительно включён в исходные усилия.
5. «Подобрать армирование» проверяет все совместные усилия каждого сечения.
   На графиках появляются минимум из проверенных вариантов и принятое
   армирование. Это дискретный подбор, не теоретическая непрерывная As.
6. Изменяйте верх/низ и количество стержней участков в таблице. Затем
   «Проверить принятое». Правка данных делает прежний результат устаревшим.
7. Сохраните проект в JSON. Результаты не восстанавливаются как проверенные
   после загрузки — пересчитайте их с текущим ядром.

Один ряд по каждой грани; добавочные стержни того же диаметра, что и фон.
Ступени сохраняют положение фоновых стержней. Например, фон 4 стержня
в каркасе → всего 7 или 10; кольцо 8 стержней → всего 16 или 24.
Положение добавочных стержней и их стыки на границах участков требуют
конструирования. Автоматического расчёта анкеровки/обрыва пока нет.

## Поперечная сила Q — первый исследовательский проход

В режиме «Стена в грунте» включите «Оценка наклонного сечения» и
задайте **физически работающие** ветви хомутов на один каркас,
диаметр, шаг и расчётное сопротивление Rsw (кПа). Количество каркасов
берётся из геометрии стены. Подтверждение выполнения требований п. 10.3
не ставится программой автоматически. Без него вклад поперечной арматуры
**не учитывается** (qsw = 0), а бетон проверяется отдельно.

В расчёте используются реальные функции `CScore.Sp63Shear`
(`ShearInclinedChecker`) закреплённой версии OpenCS. Отдельное сочетание
Q передаётся вместе с теми же N и M. Для стены преобразование из
погонного усилия в усилие на захватку выполняется **один раз**:
`Q_захватки = Q_погонное × ширина_захватки_в_метрах`.

Ограничения обязательны:
- `research_screen_pass` — только расчётная оценка одной отметки, не
  нормативная пригодность. `research_screen_fail` — превышение в такой
  оценке, `indeterminate` — расчёт недостоверен/не выполнен.
- Внутри CScore используется `ConstantProfile` для отдельной строки.
  Распределение усилий по длине, реакции/опоры, нагрузки между отметками,
  места обрыва и анкеровка **пока не восстановлены**. Поэтому полная
  проверка наклонных сечений не выполнена и наклонный момент по 8.1.35
  пока не проверяется. Нельзя использовать зелёный результат оценки
  для готовых чертежей КЖ.
- Вклад хомутов пока вводится по активным ветвям, указанным инженером;
  физическую схему их работы, применимость норм и шаги по зонам
  нужно подтвердить при полноценной интеграции.
- Круглые БНС **не подключены** к оценке Q. Спираль нельзя автоматически
  заменить обычным прямоугольным хомутом.
- В результате предусмотрены независимые поля `shear_status`,
  `shear_screening`, `shear_scope` и `shear_checked_for_design=false`.
  Поле `all_checked` относится только к **прежнему** предварительному
  подбору N/M и исследовательскому SLS; оно не разрешает выпуск КЖ.

Следующие этапы: полный профиль N/M/Q одного сочетания с сохранением
координат, совместимость `dM/dz` и знаков PLAXIS, реальные опорные
условия, участки хомутов и подтверждение продольной анкеровки. Затем
независимая численная верификация с ручными расчётами по СП 63.

## Диагностика исходных эпюр M/Q

При загрузке усилий из таблицы или PLAXIS приложение проверяет
согласованность **внутри каждой фазы/сочетания отдельно** (ULS и SLS
не смешиваются): изменение момента по глубине сравнивается с интегралом Q
между соседними отметками. Проверяются оба варианта знака `dM/ds ≈ ±Q`,
где `s` растёт вниз; программа лишь сообщает наиболее подходящий вариант
и **никогда сама не меняет знак усилия**. Сначала необходимо подтвердить
направления локальных осей и единицы PLAXIS.

Справа в разделе «Поперечная сила Q» показывается количество сочетаний,
для которых M и Q предварительно согласуются, и замечания по
несогласованным, повторным и недостаточным данным. Предел относительного
расхождения (12 %) используется **только как диагностический порог для
первого просмотра**; это не нормативный допуск точности и не разрешение
на интерполяцию. Вблизи сосредоточенных нагрузок, скачков Q, локальных
изменений осей, осреднения результатов МКЭ или приложенных пар сил
соотношение может нарушаться без ошибки расчётной модели. Тогда
инженер должен проверить источник данных.

Данные `force_profile_audit` в JSON результата и отдельный API
`/api/profile-audit` всегда содержат `usable_for_design=false`.
Совпадение M/Q **не доказывает** достаточность хомутов, достоверность
схемы опирания, работу анкеровки или полноту расчёта наклонных сечений.
Следующий этап — явная модель опор и проверка фазовых профилей в
`CScore.Sp63Shear.SampledProfile`, без автоматического угадывания
знака и без интерполяции отсутствующих сочетаний.

## Экспериментальная проверка Q по целой эпюре (следующий этап)

В режиме **«Стена в грунте»** включите **«Оценка наклонного сечения»**
и задайте фактические параметры поперечного армирования. Ниже появилась
команда **«Проверить эпюры Q для фона»**. Перед запуском:

1. Убедитесь, что в таблице для каждого ULS-сочетания присутствуют
   совместные `N, M, Q` на всех отметках (не независимые огибающие).
2. Сверьте локальные оси PLAXIS и вручную выберите
   `dM/ds = +Q` либо `dM/ds = -Q` (координата `s` направлена
   вниз по стене).
3. Подтвердите проверку осей. При изменении выбранного соглашения
   подтверждение сбрасывается.

Сначала Python проверяет согласованность эпюр по фазам и не пропускает
неоднозначные/противоречивые данные. Затем преобразует усилия на
**полную ширину захватки один раз**. В CScore вызывается
`SampledProfile` из закреплённого OpenCS, а затем
`ShearInclinedChecker`, учитывающий значения вдоль всего
выбранного сочетания. В отличие от прежней оценки отдельной
отметки здесь проверяется целая эпюра при **неизменном фоновом
продольном и поперечном армировании**.

Это ещё **не проверка стены целиком**:

- Истинные опоры/распорки, анкерные ярусы, распределённые нагрузки,
  продольные обрывы и изменение армирования по глубине не
  реконструированы. `support_model='none'`; **начала и конца
  эпюры мы не объявляем опорами**. Пограничные участки могут
  требовать самостоятельной постановки.
- Пока выполняются только условия 8.55 и 8.56. Наклонный момент
  8.63, деталировка и анкеровка не подтверждены.
- Upstream CScore при несогласованности M и Q может перейти на
  линейный M. В нашем режиме это **запрещено**: такое
  сочетание возвращает `indeterminate`.
- `research_profile_below_one` означает лишь, что
  **исследовательский коэффициент по ограниченной постановке**
  не превышает 1.0. Это НЕ нормативный «проходит».
- Результаты самостоятельны по отношению к подбору N/M, всегда
  содержат `verified_for_design=false` и
  `design_status='NOT_VERIFIED'`. Действия инженера в этой
  проверке не превращают результаты в готовый КЖ.
- Круглые БНС остаются за пределами функции.

Следующий этап — инженерная модель опирания/нагружения и
продольных обрывов, участки поперечного армирования, проверки
наклонного момента и сопоставление с независимыми ручными
расчётами прежде чем вводить автоматический подбор шагов.

## Переменный шаг поперечной арматуры — предварительный вариант

В сворачиваемом разделе **«Расчёт Q по эпюре»** доступны участки
**верх / низ / шаг, мм**. Если участок не задан, действует основной
шаг из панели Q. Зоны должны лежать в пределах стены, не перекрываться
и иметь положительный шаг. Соприкасающиеся границы разрешены.
Зоны сохраняются в `transverse_zones` рабочего проекта.

**Новая исследовательская оценка учитывает участки отдельно:** исходная
раскладка разбивается на непересекающиеся полосы с постоянным шагом.
Внутри полосы дополнительно выделяются интервалы по границам действия
соседних зон (точки переходов ±3h₀). Расчётное окно полностью
охватывает каждый новый интервал; **только пересечение положительной
длины** включает соседнюю зону, нулевой контакт на конце интервала
не распространяет редкий шаг на всю длинную полосу. Для каждой стоянки CScore получает **наибольший шаг**
из всех зон, попадающих в потенциальную проекцию наклонного сечения
в пределах ±3h₀. Это намеренно занижает принятую плотность поперечной арматуры:
чем больше шаг, тем меньше `A_sw/s`. Однако это **не доказывает**
консервативность итогового коэффициента прочности для всех ветвей формул
СП 63: при низком `qsw` меняется также выражение для `Qb`.
Поэтому подтверждение достаточности поперечной арматуры по-прежнему
запрещено, даже когда исследовательский коэффициент меньше единицы.
Результат содержит `pitch_windows` с отметками начала/конца,
принятым шагом, фактически использованным для оценки шагом,
коэффициентом использования Q и `boundary_verified=false`.
Для сравнения сохраняется прежний контрольный вариант с единственным
максимальным шагом по всей стене (`transverse_envelope`), но **он
больше не подменяет зонированный расчёт**.

Алгоритм отдельно проверяет обе стороны каждого перехода и полный
набор фазовых N/M/Q. Он не объединяет несвязанные огибающие и
не угадывает знак Q.

Это **не окончательный нормативный расчёт переходов и не автоматический
подбор шагов**. Модель учитывает неблагоприятный шаг в соседних зонах,
но пока не восстанавливает реальную дискретную раскладку стержней вдоль
каждой наклонной трещины, реальное опирание и анкеровку.
Нельзя считать результат разрешением на разрежение хомутов в отдельных
участках — `boundary_verified=false`, `verified_for_design=false`.
Физическая схема хомутов, опоры, обрывы и анкеровка остаются отдельными
условиями верификации. При редактировании участков подтверждение
конструктивных требований п. 10.3 сбрасывается.

Следующий шаг: расчёт с `qsw(s)` и реальной дискретной раскладкой
хомутов на интервале каждой критической проекции, отдельно для каждой
стадии и обеих сторон проверки, с контролем переходов между зонами
и проверкой наклонного момента.

## Предложенная дискретная раскладка хомутов — геометрическая диагностика

Добавлен **отдельный от расчёта прочности** модуль условного размещения
хомутов. Он разворачивает участки с заданным шагом в отметки отдельных
поперечных стержней. По умолчанию **предполагается** один первый
хомут точно в начале каждого участка; эта координата не берётся из
чертежей и не подтверждена инженером. На общей границе не создаются
два одинаковых хомута.

Для каждого полного ULS-профиля ядро CScore дополнительно возвращает
критическое наклонное сечение по формуле (8.56): координату стоянки,
проекцию C и **направление** (вверх/вниз). Это отдельная критическая
проекция по поперечной силе: при определяющем условии (8.55) она может
не совпадать с общим максимумом коэффициента Q.

Модуль раскладки сообщает число **предполагаемых** хомутов одного
каркаса, пересекаемых этой проекцией. Стержень ровно в стоянке
исключается, ровно в дальнем конце включается для обоих направлений.
Если C выходит за пределы имеющихся отметок эпюры, выдаётся
`outside_sampled_profile` и число хомутов не вычисляется.
Сильное сгущение сверх допустимой памяти, повторные или разорванные
участки отклоняются.

Поле `proposed_stirrup_layout.status = UNVERIFIED_PROPOSAL`.
У всех `critical_projection_links` остаются
`verified_for_design=false`, `actual_layout_confirmed=false`.
Количество пересекаемых хомутов **не используется** для вычисления
Qsw, не даёт разрешения на выпуск КЖ и не доказывает действие
наклонного сечения по СП 63. Для перехода к нормативному расчёту
необходимо явно задать первые/последние хомуты по рабочим чертежам,
замыкание, анкеровку, число фактически работающих ветвей, реальное
опирание и способ суммирования сопротивлений на наклонной трещине,
после чего выполнить независимую численную верификацию.

## Хомуты по фактическим координатам (геометрия, не прочность)

В разделе **«Расчёт Q по эпюре → Фактические отметки хомутов»**
доступны два режима: прежняя условная раскладка по шагу
и **«Введённые отметки»**. Для второго вводится список расстояний от
верха стены **в мм**, разделённых пробелами либо точкой с запятой.
Дробные миллиметры допускают десятичную запятую, например
`50; 250; 450,5; 650,5`. Положение каждого хомута должно
возрастать и находиться в пределах длины расчётной эпюры.

В отличие от условной сетки, модуль геометрии использует **только
перечисленные пользователем** координаты. Для каждого участка
контролируется максимальное расстояние между соседними стержнями,
до его начала и до конца; участок без единого хомута или с
расстоянием, превышающим принятый шаг, отклоняется до запуска CScore.
Общий стержень на границе участков учитывается один раз.

Флажок **«Координаты сверены с раскладкой каркаса»** подтверждает
только *геометрию*. При изменении шага или границ участков подтверждение
сбрасывается. При замене исходной эпюры таблицей либо PLAXIS введённые
координаты сбрасываются, чтобы не использовать раскладку от старой стены.
Старые проекты без раздела `transverse_layout` по-прежнему открываются
как проекты с условной раскладкой.

Результат содержит `proposed_stirrup_layout` (историческое имя ключа)
со статусом `SPECIFIED_GEOMETRY_ONLY` либо
`SPECIFIED_NOT_CONFIRMED`; в `critical_projection_links` при
попадании проекции в расчётную область — статус
`specified_layout_count_only`. Для всего расчёта
**`verified_for_design=false` неизменен**. Координаты хомутов
пока **НЕ используются** при вычислении Qsw в CScore. Это необходимо,
поскольку для нормативного вклада в прочность ещё предстоит подтвердить
анкерное устройство хомутов, работающие ветви, модель опирания и
корректность применения формул для переменного шага.

## PLAXIS 2D v22.01
Подключение: Output → включить Remote Scripting Server → в приложении
«Из PLAXIS» → порт Output и пароль → выбрать элементы одной вертикали
и фазы. Импорт только читает результаты, не меняет расчётную модель.
Для прямой связи используемый Python должен иметь `plxscripting` из среды
PLAXIS. При отсутствии модуля приложение объяснит причину; таблицу Output
можно перенести через Excel. Автоматической установки пакетов нет.

Выдача X/Y/N/M/Q запрашивается для выбранного объекта и фазы с одним
расположением `node`. Типы результатов проверяются при подключении.
Названия фаз дополняются уникальным идентификатором, чтобы одинаковые
описания не смешивали сочетания. Пропущенные результаты не заменяются нулём.

Выберите единицы модели (N/kN/tf, mm/cm/m) и подтвердите масштаб по
таблице Output. Для Plate ожидаются погонные усилия. Для Embedded Beam
масштаб на метр/на элемент задаётся явно: Bentley изменил его в 2023.1,
и поведение этой версии нельзя автоматически переносить на v22.01.
Исходный масштаб сохранится; шаг свай применяется в расчётной модели.

Импорт SLS целиком как длительное воздействие требует отдельного
подтверждения. Для разных полных/длительных моментов сначала перенесите
данные и задайте `basis=SLS` и `m_long` в таблице. Ядро пока принимает одну N
для полной и длительной составляющей; разные N не поддержаны.

Не интерполируем разные сетки фаз: наборы отметок выбранных сочетаний
должны совпадать. Повторные строки на общей отметке сохраняются и
проверяются независимо; локальная потеря данных не скрывается огибающей.

## Границы результата
Только вертикальные конструкции и один изгиб. Q проверяется лишь отдельной исследовательской локальной оценкой, не нормативным расчётом наклонных сечений.
Нет автоматической проверки устойчивости, анкеровки и конструктивных норм.
SLS остаётся исследовательским; все результаты NOT_VERIFIED для выпуска КЖ.
Зоны построены по заданным отметкам, без доказательства выполнения условий
между ними. В местах пропуска/несходимости подбор не выдаёт ложный допуск.
