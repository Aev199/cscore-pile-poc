# SLS: три случая только кратковременного трещинообразования и восемь тяжёлых сочетаний

Дата: 2026-10-16. Все результаты исследовательские. Не использовать как окончательную проверку СЛС/КЖ.

## Основание

Данные: успешный Windows CI https://github.com/Aev199/cscore-pile-poc/actions/runs/38868762683, 70 сочетаний, 11 indeterminate; исходный расчёт `sls_matrix_aligned/*_output.json` и независимые исправленные SAV/RTF АРБАТ 21.1.9.3. Первоначальный CScore pin 4ae6aa077be5b29145930ec093ba1c9eb7776222.

**Достоверно из pinned исходника OpenCS** `CScore/CrackWidthSolver.cs`: в Compute после CrcSolver делается `if (mLong <= mcrc || !crcRes.StrainPlane.HasValue) return zero;`, до обработки полной нагрузки. Поэтому при mLong<=Mcrc<Mtotal прежний ответ не мог содержать кратковременное раскрытие, даже если полнонагрузочное состояние имеет трещины. Другие места возвращают такой же zero при несходимости или отсутствии растянутой арматуры; поэтому статус Cracked=false над Mcrc нельзя интерпретировать как истинное отсутствие трещин.

## Три случая порогового разделения

| Сечение/сочетание | Mlong, кН·м | Mtotal, кН·м | Mcrc CScore, кН·м | Критическая оговорка |
|---|---:|---:|---:|---|
| R500×700 T09 | 80.0 | 160.0 | 121.53 | АРБАТ всё же печатает длительное раскрытие; пороговые модели расходятся |
| R500×700 T10 | 80.62 | 161.25 | 96.20 | У АРБАТ длительная N отличается: коэффициент 0.5 на продольную силу |
| C800/16Ø25 T09 | 80.0 | 160.0 | 155.56 | Для этого сочетания АРБАТ не печатает ширину |

В отдельной ветке НАШЕГО C#-адаптера при совпадающих направлениях полной и длительной изгибающей нагрузки повторно вызывается неизменённый `CrackWidthSolver.Compute(N, Mtotal, Mtotal)`; используется компонент `Acrc2` (φ1=1.0) для **только кратковременного** раскрытия. Продолжительное значение по нашей расчетной модели принимается нулём **только как исследовательский результат** при данном Mcrc, без заявления, что АРБАТ с этим согласен. Дополнительная проверка требует CrcConverged, PlaneLong, Cracked=true и тождества `Acrc2≈AcrcLong/1.4` при повторном расчёте.

Предварительный консервативный результат для кратковременной части = `max(Acrc2, Acrc2/ψs2)`. Для `native_refined` сохраняется уточнённая методика = `Acrc2`. При K≤1+review_band оба варианта ПРИНУДИТЕЛЬНО получают `preliminary_decision=engineering_review`, даже при K<1. При явном превышении K>1+review_band статус `preliminary_exceeds_limit`. Автоматический предварительный допуск запрещён в обоих вариантах, пока не разрешено различие Mcrc. Выходное поле `crack_solver_path=supplemental_full_load_Acrc2`, причина `cracked_only_under_total_load_unvalidated_mcrc_threshold`. В статистику совпадения с АРБАТ такие расчёты не включаются.

Не поддерживаются обратные/поворотные направления M при разделении полной/длительной составляющих — там сохраняется indeterminate. Подавать в `CrackWidthSolver` разные Nlong/Ntotal текущий контракт также НЕ умеет.

Во всех восьми случаях число получено из независимого RTF АРБАТ; **это не доказанная причина отказа SLS-решателя**. Физически нельзя допускать их в проект по текущей прочности. Наш адаптер помечает источник неопределённости `upstream_post_threshold_zero_unresolved_stage` и оставляет расчёт без ширины. Не добавлять численную заглушку, догадки или «компенсирующую» ширину в этих состояниях.

## Критерии ближайшей Windows сборки

1. 66+ контрактных тестов и 486 upstream тестов проходят без регрессии, оригинальный CScore не изменён.
2. Из отдельно исследованных трёх случаев хотя бы один возвращает численную кратковременную ширину; успешные случаи помечаются `engineering_review`, без выбора арматуры.
3. Восемь состояний над порогом Mcrc сохраняют неопределённость, не превращаются в нули или «проходит».
4. Сравнительная статистика АРБАТ не включает восстановленные кратковременные значения как доказанные равные эталону; геометрические ограничения прямоугольников также остаются.
5. Только после успешной сборки анализируется изменение счётчика 59/70 и качество новой диагностики; до неё никаких результатов улучшения сходимости не объявлять.

Если опытный результат не сходится — перепроверять решатель по данным, а не отключать fail-closed. Следующая отдельная задача: показать статус внутреннего SolveDamped для 8 тяжёлых случаев и отдельно согласовать Mcrc/материальные SLS характеристики с АРБАТ.
