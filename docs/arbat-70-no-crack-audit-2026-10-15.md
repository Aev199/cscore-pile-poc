# АРБАТ: независимые 70 случаев — первый аудит исходных RTF/SAV (2026-10-15)

## Происхождение

Пользователь выполнил 7 пакетов по 10 сочетаний и предоставил пары \`300x500.rtf/sav\`, \`400x600.rtf/SAV\`, \`500x700.rtf/sav\`, \`400x400.rtf/sav\`, \`d600.rtf/sav\`, \`d800.rtf/SAV\`, \`d1000.rtf/SAV\`.

АРБАТ 64 бит **21.1.9.3 от 27.03.2019**, СП 63.13330.2018, бетон B30, A500, коэффициент бетона gb1=0.9, длина 3 м, конструкция статически определимая.

Исторический CScore для сопоставления: Windows Actions [38761812114](https://github.com/Aev199/cscore-pile-poc/actions/runs/38761812114) @ \`dd22596c4efce583809f89db4f2b246dacf99c32\`. Экспериментальная матрица в артефакте \`sls_matrix/cross_section_sls_matrix.csv\`, отдельные \`*_input.json\` и \`*_output.json\`.

**Проверено:** каждый SAV содержит 10 силовых записей, каждый RTF — 10 соответствующих строк. Для всех **70** подтверждено совпадение N, My(АРБАТ) = Mx(CScore), Mz(АРБАТ) = My(CScore) численно и по порядку, Q=0. Физическое направление осей/размещение арматуры прямоугольников ещё требует графической сверки.

## КРИТИЧЕСКОЕ: другой вид трещиностойкости

**Во всех 7 RTF указано «Трещиностойкость — Отсутствие трещин».** Следовательно, здесь проверяется соблюдение условия отсутствия образования трещин (например, \`Деформации в растянутом бетоне\`), а НЕ допустимая ширина \`a_crc\`.

Невозможно честно вычислить MAPE между коэффициентом по деформациям растянутого бетона и коэффициентом \`a_crc/a_crc,ult\`, сформированным CScore. В этих RTF **не дано ни одного значения ширины трещины**.

См. справку разработчика: https://scadsoft.com/help/Arbat/ru/Arbat1049_rtf/CrackData.htm — нужно выбрать проверку ограниченной ширины раскрытия и задать предельные значения.

Для семи оставшихся строк АРБАТ не печатает проверку растянутого бетона, например при грубом нарушении прочности. **40 нарушений относятся к требованию отсутствия трещин, а не к допустимой ширине.** Не трактовать их как 40 случаев непрохождения обычной проверки \`a_crc\`.

Отдельно следует тестировать \`CrackingSolver\` по возникновению трещин; эти 70 файлов применимы к такой задаче, но ещё необходимо согласовать нормативные свойства бетона, геометрию и вид проверки.

## Несоответствия входных данных

1. **T09 (7 случаев):** АРБАТ \`Коэффициент длительной части = 1\`, а CScore \`Mx_long=80\`, \`Mx_total=160\` кН·м. Для сопоставимости нужно **0.5** в АРБАТ.
2. **T10 (7 случаев):** АРБАТ \`Коэффициент длительной части = 0.5\` применяет к группе N/M. CScore подаёт \`N=-250 kN\` и для полной, и для длительной нагрузки; его pinned \`CrackWidthSolver\` принимает только ОДНУ N. Поэтому длительная часть сжатия не эквивалентна; случай нельзя считать полноценно согласованным, даже если моменты длинной части 70/40 кН·м совпадают.
3. **400×400 (все 10):** АРБАТ отчёт: \`S1 — 4Ø16, второй ряд 4Ø16; S2 — 4Ø16, второй ряд 4Ø16\` => **16** стержней; CScore вход: **8** стержней (две группы координат по x=±157 мм, y=±157,±90 мм). Геометрии не совпадают!
4. **Прочие прямоугольники:** одинаковых диаметра и общего числа стержней недостаточно для доказательства идентичной схемы: \`S1/S2\` в АРБАТ и индивидуальные координаты CScore могут обозначать разные грани/раскладки. Проверять графически и по внутренним характеристикам сечения. Для 500×700 CScore имеет арматуру по 8 точкам периметра, ARBAT по 4 стержня на каждую из двух сторон.
5. Версия АРБАТ 2019 существенно старше независимого эталона из более поздней версии (пакеты Ø800/Ø1000); не агрегировать разницу версий в один «подтверждённый» эталон.

## Приоритет исправления при повторном прогоне

- **Не перепечатывать 70 усилий.** Открыть каждый сохранённый SAV и в АРБАТ на вкладке \`Трещиностойкость\` выбрать проверку **ограниченной ширины раскрытия** (вместо «Отсутствие трещин»), задать одинаковые в обеих программах пределы, например \`0.3 mm\` для длительного и \`0.4 mm\` для кратковременного (они уже использованы в экспериментальном CScore; проверить допустимость их выбора по конкретным условиям).
- Исправить T09 на коэффициент длительной части 0.5; T10 временно помечать несопоставимым по длительной N, пока не будет исправлена модель SLS в нашем адаптере.
- До общей статистики сверить координаты арматуры и доступность схемы в АРБАТ. 400×400 пересоздать с **точно одинаковыми** 8 либо 16 стержнями; произвольная «похожая» раскладка не допускается.
- Отдать RTF после перерасчёта. Исходные SAV/RTF хранить отдельно, не перезаписывать.
- Только после этого сравнивать \`a_crc,long\` и \`a_crc,short\` в мм, плюс их отношения к пределам, отдельно для native CScore и предварительно-консервативного метода. При неуспехе CScore оставлять \`indeterminate\`.

Инструмент \`arbat_sav_export.py\`, написанный ранее для ДВУХ откалиброванных круговых шаблонов на 8 загрузок, **НЕ** применять к новым 10-загрузочным SAV. Новый формат и прямоугольные конфигурации не подтверждены для записи.

**Итог:** полученные 70 расчётов ценны как независимая база проверки *трещинообразования*. По *раскрытию трещин* численных эталонов в них нет. Не подменять один критерий другим.
