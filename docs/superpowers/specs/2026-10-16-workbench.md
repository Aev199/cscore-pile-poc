# Локальный интерфейс расчёта КЖ

Согласованная цель: ручные усилия / PLAXIS 2D v22.01 Plate и Embedded Beam
Row → эпюры → подбор фона и усилений → ручная корректировка инженером.
Plate может представлять стену или БНС. Каркасы стены одинаковые, 1–3.

Локальное приложение на Python stdlib: сервер только 127.0.0.1, встроенные
HTML/CSS/JS без сети, системный браузер. Запуск bat/python, существующий
CScorePileRunner.exe рядом. Нет Node/Python сторонних зависимостей для UI.

## Усилия
Строка: z (отметка), case, basis (ULS/SLS), n, m, q, m_long (только SLS).
Сохраняем совместные N/M/Q каждой фазы/точки, в том числе разные результаты
на совпадающей отметке. Не собираем расчёт из независимых огибающих.
Разные наборы отметок выбранных фаз требуют согласования: не интерполируем
и не заполняем пропуски нулём. Вертикальная конструкция, один изгиб.
SLS имеет одну N для полной/длительной части (ограничение ядра).
Q показывается, но не проверяется. Данные вводятся в кН, м, кН·м;
исходный масштаб — на метр либо на сваю; для сваи из погонных усилий
умножаем на шаг один раз. Для стены только на метр. Пользователь подтверждает
направление M и основание ULS/SLS; не назначаем коэффициенты нагрузок сами.

## PLAXIS
Подключение к локальному Output через установленный plxscripting, только чтение.
При отсутствии пакета понятная ошибка с возможностью использовать Python
поставки PLAXIS. Каталог объектов/фаз, выбор нескольких объектов одной
вертикальной конструкции и фаз. Capability-check ResultTypes, без eval.
Импорт на одну basis за операцию, добавление к общей таблице. Проверяем
длины массивов, вертикальность, конечность; не экспортируем огибающие.
Единицы исходного проекта подтверждаются инженером. Обнаруженные GeneralInfo
показываются как справочная информация. Для EBR v22.01 не назначаем масштаб
по названию: инженер выбирает per_metre/per_member по таблице Output.
Bentley сообщает изменение выдачи EBR в 2023.1 (KB0107881, issue 740143),
поэтому эта неопределённость видна до импорта. Локальный PLAXIS здесь недоступен.

## Подбор и редактирование
Геометрия/материалы — существующие форматы ядра. Геометрия в обычных полях,
полный набор материалов и SLS-параметров доступен отдельной JSON-формой.
Демо явно иллюстративное; проверка материалов обязательна перед расчётом.
Фон задаётся инженером. Поиск добавляет стержни того же диаметра, сохраняя
фон: для стены n=(n0-1)*tier+1 по каждой грани, для БНС n=n0*tier, tier 1..3.
Положение фоновых стержней сохраняется в равномерной раскладке.
Полный перебор вариантов в каждой отметке, все ULS → затем SLS. Поиск
нормального сечения; статусы непригодности/неопределённости не дают допуска.

Зоны между соседними отметками получают покомпонентный максимум tier
соседних выбранных сечений, затем одинаковые зоны объединяются. Каждое
принятое сечение перепроверяется ядром, монотонность As не предполагается.
Редактор зон меняет отметки и tier; зоны не перекрываются внутренностями.
Фон неизменен по длине. На общей границе действует максимум tier.
Анкеровка НЕ автоматизирована: расчётные границы зон явно не являются
готовыми отметками обрыва стержней. За пределами дискретных отметок
проверка не заявляется. Инженер может расширять зоны, затем перепроверить.

## UI
Три области: данные, SVG эпюры N/M/Q и As (две грани/кольцо), инспектор.
Щелчок на эпюре выбирает ближайшее сечение; фазовый фильтр только отображение.
CSV/TSV вставка, JSON загрузка/сохранение проекта, таблица зон и свойства,
асинхронный запуск и индикатор прогресса. Любая правка инвалидирует результат.
Пароль PLAXIS не сохраняется в проекте/журнале. Локальные запросы с session
header и проверкой Origin; ограничение размера тела; сервер не читает
произвольные файлы по HTTP и не принимает команды оболочки.

## Проверка
Python tests: единицы/шаг, пропуски фаз, строгий ввод, вложенность раскладок,
огибающие и зоны, SLS gate, сохранение проекта без секретов.
Browser tests: ввод, эпюры, выбор, редактирование, invalidation, сохранение.
Windows CI: существующие проверки + workbench smoke с настоящим CScore.
