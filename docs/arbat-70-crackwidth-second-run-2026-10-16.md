## Важные причины ограничить количественное сравнение

1. Трактовка a1: официальная справка SCAD https://scadsoft.com/help/Arbat/ru/Arbat1049_rtf/ResistRC.htm прямо различает режимы. Для штучных арматурных стержней a1 — защитный слой, для режима площадей арматуры — расстояние до центров тяжести. Для новых RTF с S1=8Ø20 и аналогичными заданиями CScore кругового сечения правильно использует r=D/2−a1−Ø/2. Прежнее безусловное предположение «a1 всегда до оси» ошибочно.
2. 400×600 и 500×700: RTF задают S1/S2=3+3 и 4+4, исходная матрица CScore размещала промежуточные стержни на иных гранях. Не утверждать совпадение!
3. 400×400: теперь 8 стержней в обоих моделях, но ARBAT использует 20 мм в свету между первым и вторым рядами. В предыдущем CScore геометрия рядов была другой.
4. T10: упрощённая форма АРБАТ применяет коэффициент длительной доли 0.5 также к N=−250 кН. Pin CScore CrackWidthSolver использует одинаковую осевую N для длительной и полной частей. Строго сравнивать T10 нельзя.
5. Во многих RTF при нарушениях ULS ширина не печатается. Не делать из такого пропуска вывода о ширине трещины. Особое исследование: Ø600 T01 и Ø800 T02/T03: в CScore есть положительная ширина, в ARBAT соответствующие строки отсутствуют.
6. Нормативные служебные диаграммы CScore ещё исследовательские; скрытые пути fallback/несходимости CrackWidthSolver сохраняются.

## Следующий эксперимент без повторного ввода данных в АРБАТ

Исходную матрицу не меняем. Отдельный ключ --layout arbat_stated перестраивает только прямоугольную арматуру (предположение по RTF): 400×600 по 3 стержня на двух противоположных гранях, 500×700 по 4, 400×400 два ряда с межцентровым расстоянием 36 мм (Ø16 + 20 мм в свету). Круглые остаются неизменными. Расположение осей и координаты прямоугольников пока требуют визуальной проверки.

Новый Windows workflow отдельно запускает этот вариант в results/sls_matrix_aligned и tools/compare_arbat70_crackwidth.py, сохраняет 70 строк сравнения и summary. Переменные геометрии и разные длительные N не признаются точным сопоставлением. Независимые численные эталоны хранятся в examples/verification/arbat_matched/arbat70_crackwidth_20261016.json; отсутствующее значение — null.

Окончательное инженерное решение в модуле остаётся таким: основной предварительный arbat_conservative, уточнённый native_refined — опциональный по выбору пользователя. Ни один исследовательский результат не является самостоятельным допуском армирования к выпуску КЖ.
